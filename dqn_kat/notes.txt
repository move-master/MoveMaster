Things I want the agent to have access to:
- CoM of the tower
- Height of the tower (including distance of the blocks from the top)

- Discourage the agent from removing blocks from the base when possible
- Encourage the agent to make moves that keep the CoM as centered as possible
- Discourage the agent from removing blocks from layers that have 2 blocks
- Rule of no picking from top layer / incomplete second-to-top layer should be HARDCODED in action space

The maximum amount of transition states my algorithm would have to calculate is 153, as this reflects the number of possible first moves on a fresh 3x18 Jenga tower.
Explanation:
54 blocks in total, but top layer is never in play. So...
- # of Movable blocks: 54 - 3 = 51.
- # of Places: 3.

51 * 3 = 153 possible moves at the start of Jenga. This is the largest possible action space in a classic Jenga game at any point in the game.

---------------------------------------------------
After writing getSuccessors() and running this recursively, it seems computationally expensive to generate the entire state space for Jenga...
For a 3x2 tower, running getSuccessors() recursively outputs 12 states. This is correct.
For a 3x3 tower, running getSuccessors() recursively outputs 154 states.
For a 3x4 tower, running getSuccessors() recursively outputs 2,210 states.
For a 3x5 tower, running getSuccessors() recursively outputs 31,080 states.
Seemingly, the number of possible states scales exponentially with every additional layer added.

So, we will have to find a way to work around not having access to the entire state space.

Good news is, the state space is still finite, so we should be able to proceed with DQN.

Also, getSuccessors() is easily converted to a non-recursive function, only generating the successor states for a single state, and no further successors.
